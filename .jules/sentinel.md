## 2025-06-09 - XSS Vulnerability via Improper HTML Attribute Sanitization
**Vulnerability:** The HTML escape mechanisms in `app/vault.js` and `app/components/vault/components/vault-view.js` failed to escape single quotes (`'`) and double quotes (`"`) effectively in all contexts, leading to potential Cross-Site Scripting (XSS) via attribute injection. In `vault.js`, `div.innerHTML` was mistakenly assumed to escape quotes.
**Learning:** Browser DOM implementations (or mocks) do not consistently escape quotes when retrieving `innerHTML` unless the text explicitly creates an attribute context. Directly interpolating unescaped/semi-escaped input into HTML attributes (e.g., `<div data-password="${escapeHtml(input)}">`) allows attackers to breakout of the attribute string and inject event handlers (like `onload=alert(1)`).
**Prevention:** Always use explicit string manipulation (e.g., regex replacement) that rigorously covers all 5 critical structural characters (`&`, `<`, `>`, `"`, `'`) when escaping text intended for HTML interpolation. Validate output sanitizers using PBT.
