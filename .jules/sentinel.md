## 2024-11-20 - XSS vulnerabilities when non-strings and single quotes bypass escape routines
**Vulnerability:** The HTML escape function threw TypeErrors when given non-string values (like integers or booleans) because `.replace` is a String method, leading to component rendering failure and potential fallback attacks. Furthermore, single quotes were not escaped, allowing XSS in single-quote delimited attribute contexts.
**Learning:** Escape functions must be defensive and accept any primitive value securely without failing. In JS, `String(str)` explicitly casts values safely. Single quotes (`'`) must be escaped (`&#39;`) just as double quotes are.
**Prevention:** Always cast inputs in Regex-based HTML escape functions and check `if (str == null)` rather than `if (!str)` to avoid stripping valid falsey values like `0`. Always escape all 5 critical structural characters (`&`, `<`, `>`, `"`, `'`).

## 2024-11-20 - Unescaped Modal Attributes cause Attribute Injection XSS
**Vulnerability:** The `ModalManager` dynamically generated `.innerHTML` modal templates using unescaped parameters (like `label`, `message`, `val`, and `title`), leading to Attribute Injection XSS (e.g., payloads escaping via `"` and `'` characters in input elements). Similarly, the legacy UI `escapeHtml` function relied on a broken `div.textContent` to `.innerHTML` pattern that did not escape quotes.
**Learning:** `div.textContent = text; return div.innerHTML` is a flawed anti-pattern for sanitization as it completely fails to escape attribute boundaries (`"` and `'`). All structural HTML characters must be rigorously sanitized using standard regex string replacements in dynamic template strings.
**Prevention:** Never use the `textContent` injection trick for sanitizing attributes. Always strictly enforce a 5-character string replacement regex (`&`, `<`, `>`, `"`, `'`) for any unsanitized user-generated property injected into an HTML template structure.
