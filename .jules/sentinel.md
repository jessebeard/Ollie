## 2024-05-18 - Fix HTML Attribute Injection XSS
**Vulnerability:** The HTML escape functions `escapeHtml` in `app/vault.js` and `escape` in `app/components/vault/components/vault-view.js` failed to escape single (`'`) and double (`"`) quotes. They were escaping only `&`, `<`, and `>`. Because the vault renders variables dynamically into attributes (like `data-value="${this.escapeHtml(entry.password)}"`), an attacker could provide an entry password with quotes, breaking out of the attribute context and executing arbitrary JavaScript via event handlers like `onmouseover` or `onclick`.
**Learning:** `div.textContent = str; return div.innerHTML` is an insufficient mitigation for preventing Cross-Site Scripting (XSS) when placing variables inside HTML attributes, because it only prevents tag injection.
**Prevention:** Explicitly use Regex mapping that covers all structural characters: `&`, `<`, `>`, `"`, and `'`. Ensure inputs are always cast to `String()` first to avoid throwing exceptions when numbers or booleans are passed. Added a Property-Based Test (PBT) asserting that random generative inputs do not contain unescaped structural symbols.
